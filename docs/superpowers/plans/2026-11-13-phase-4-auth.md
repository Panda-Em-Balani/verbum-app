### Task 2: Auth state hook

**Files:**
- Create: `src/auth/useAuth.js`, `src/auth/useAuth.test.jsx`

**Interfaces:**
- Produces a module store (pattern of `src/progress.js`):
  - `useAuth(): { status: 'loading'|'signedOut'|'needsName'|'signedIn'|'recovery', user: { id: string, email: string, name: string } | null }`.
  - `startAuth(): () => void`: subscribes to `supabase.auth.onAuthStateChange` once; returns unsubscribe. Called from `App.jsx` in an effect.
  - `setProfileName(name: string): Promise<{ ok: boolean, error?: string }>`: upserts `profiles { id, name }`; on success status → `signedIn` and caches the name.
  - `signOut(): Promise<void>`.
- Event handling (inside the callback, never `await` a Supabase call directly: defer the work with `setTimeout(fn, 0)`, as Supabase's docs require, to avoid a lock-up):
  - `PASSWORD_RECOVERY` → status `recovery`, user from the session.
  - `INITIAL_SESSION`, `SIGNED_IN`, `TOKEN_REFRESHED`, `USER_UPDATED` with a session → `resolveProfile(user)` unless status is `recovery` (a recovery session stays in `recovery` until `updatePassword` succeeds; then call `markRecovered()`, exported, which runs `resolveProfile`).
  - `INITIAL_SESSION` without a session, and `SIGNED_OUT` → `signedOut`, user `null`, remove nothing else.
  - `resolveProfile(user)`: select `name` from `profiles` where `id = user.id` (`maybeSingle()`).
    - name found → `signedIn`; cache it in `localStorage['verbum_profile_name_' + id]`.
    - no row and `user.user_metadata?.name` → upsert `{ id, name }`, then `signedIn` (no prompt).
    - no row and no metadata name → `needsName`.
    - request error (offline) → `signedIn` with the cached name or `""`. Never `needsName` on an error.
  - Calling `resolveProfile` twice for the same user id while one is in flight does nothing.

  - "SIGNED_OUT clears the user".
